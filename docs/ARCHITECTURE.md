## ۱. لایه‌بندی سیستم‌ها (Layered Architecture)

```
+-----------------------------------------------------------+
|                      Presentation                         |
|   (CanvasRenderer, Camera2D, HUD, PauseMenu, DevDossier)  |
+-----------------------------+-----------------------------+
                              | observes state & events
                              v
+-----------------------------------------------------------+
|                       Game Flow                           |
|       (Boot, SceneManagement, Pause/Resume, Reset)        |
+-----------------------------+-----------------------------+
                              | manages
                              v
+-----------------------------------------------------------+
|                      Simulation                           |
|    (World, TileMap, CollisionSystem, PlayerController,    |
|       Traffic, NPCBehavior, PoliceDispatch, Economy)      |
+-----------------------------+-----------------------------+
                              | uses
                              v
+-----------------------------------------------------------+
|                         Core                              |
|   (SimulationClock, Vector2, EventBus, SeededRandom,      |
|             EntityID, StateSerializers)                   |
+-----------------------------------------------------------+
```

## ۲. اصول مرزهای مسئولیت (Separation of Concerns)

1. **لایه Core:** کاملاً مستقل از محیط گرافیکی است. محاسبات ریاضی، زمان، انتشار رویدادها و شناسه موجودیت‌ها در این لایه قرار دارند.
2. **لایه Simulation:** مسئول اجرای منطق شهر، فیزیک برخورد، هوش NPCها، قوانین جرم و اقتصاد است. این لایه مستقیم هیچ المنتی در Canvas رسم نمی‌کند، بلکه وضعیت (State) تولید کرده و رویدادها را صادر می‌کند.
3. **لایه Presentation:** وضعیت جاری را می‌خواند و روی Canvas 2D ترسیم می‌کند. موقعیت دوربین، جلوه‌های نور و منوها در این لایه مدیریت می‌شوند.
4. **لایه UI:** وضعیت‌های کاربر، مکث، آمار و پیام‌ها را نمایش داده و ورودی‌های تنظیمات را به دستورات معتبر تبدیل می‌کند.

## ۳. الگوی رویدادها (Event-Driven Communication)
تمام رخدادهای مهم شهر بر بستر `EventBus` منتقل می‌شوند:
- `event_id`: رشته یکتا با شمارنده مونوپتونیک
- `tick`: شماره گام شبیه‌سازی
- `event_type`: نام رسمی رویداد (مانند `PlayerMoved`, `CollisionOccurred`, `GamePaused`)
- `actor_id`: عامل ایجادکننده
- `payload`: داده‌های دقیق رخداد
